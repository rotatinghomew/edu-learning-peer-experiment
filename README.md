# 同伴带动与交叉接触下的邀学试验决策

这是一个面向社区老年教育运营的本地分析原型，使用合成记录演示从业务登记到运营决策的处理。项目把记录读取、抽签设计、暴露支持度、因果效果和社区级预算决策分开，便于核对原始事实与派生结果。

## 环境与使用

需要 Python 3.11 或更高版本，无第三方依赖。

- 执行测试：`python3 -m unittest discover -s tests -v`
- 查看原始到课汇总（运营核账口径）：`python3 -m learning_peer_experiment.report`
- 查看同伴试验分析与决策包（JSON）：`python3 -m learning_peer_experiment.trial_report`
- 重新生成固定种子的合成试验登记：`python3 -I scripts/generate_trial_data.py`

也可使用 Docker：`docker build -t learning-peer-experiment .`，再执行 `docker run --rm learning-peer-experiment`（容器默认运行原始汇总）。所有记录均为本地合成数据，不包含个人信息。

## 数据登记（`data/trial/`）

| 文件 | 内容 | 分析用途 |
| --- | --- | --- |
| `design.csv` | 抽签单位（社区）、可分方案、登记概率、方案邀请比例 | 唯一的随机化来源，概率在每个社区内和为 1 |
| `persons.csv` | 试验花名册 | 分母与抽签单位成员 |
| `assignments.csv` | 抽签分配 Z（社区共同受分配） | ITT 与暴露定义的唯一处理依据 |
| `notifications.csv` | 个人实际通知 D | 只做不依从标记，不能当作随机分配 |
| `attendance.csv` | 个人到课 Y | 结果 |
| `edges.csv` | 关系边与 `pre_treatment` 标记 | 课后新增边（`pre_treatment=0`）一律拒收，不能回溯定义入组前同伴 |
| `budget.csv` | 下一轮邀请名额预算 | 按社区整体占用 |

## 分析流程与口径纪律

1. **登记校验（`trial_records.py`）**：概率和为 1、抽签结果落在登记设计内、社区内方案唯一、各类记录覆盖花名册；课后新增边严格拒收（可审计后剔除）。
2. **设计与暴露（`design.py`）**：暴露格子只由抽签 Z、登记邀请比例与入组前网络定义（E0 无人受邀 / E1 仅同伴受邀 / E2 仅本人受邀 / E3 联合暴露）。边分为组内、跨社区-试验内、跨出登记设计边界三类。支持度同时报告“设计期望人数”和“本轮实现人数”：设计为正但本轮为空是**证据缺口**，不是零效果。
3. **因果效果（`causal.py`）**：
   - 保留**按原分配的 ITT**，以社区为推断单位，采用登记设计全枚举的随机化推断（RI）与加性效应反演置信区间，个人数只作描述性分母；
   - 仅在 E0/E1 都有设计概率且本轮都有实现时，报告**同伴暴露对比**，并写明分母、跨抽签边界限制与不可估计格子；
   - 跨社区边存在时，社区级 ITT 仍是有效政策效果，但把同伴效果归因到单一社区的结论不成立；跨出设计边界的人员单独标注。
4. **社区级决策（`planning.py`）**：名额按“社区 × 登记方案”整体占用，不产生个人预测分数。效果证据只取 ITT 方案效果（已包含同伴带动），同伴对比只作机制解释、不叠加，避免受邀者之外的收益被重复计算。预算内枚举全部方案：
   - **可比方案**：只产生本轮有实现对象的暴露格子，给期望增量到课与社区自助法 95% 区间；
   - **不可比方案**：依赖试验从未支持的暴露程度（如本轮 E3 未实现），保留缺口、不外推确定收益；
   - 登记概率为 0 的社区方案只登记为未支持选项，不产生收益数字。

## 口径保留

原始到课汇总（`learning_peer_experiment.report` 与 `data/observations.csv`）的人数口径完全不变，仍供运营核账；新增分析只读取登记数据并写入临时 SQLite，不修改任何原始 CSV。SQLite 数据库在调用时创建于临时目录。
